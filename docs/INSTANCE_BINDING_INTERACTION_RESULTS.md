# 实例承载关系交互改进（rc2）

日期：2026-11-03。版本：1.1.0-rc2，DLL 文件版本 1.1.0.1。目标：SOLIDWORKS 2025 SP5.0。

## 本次变更

- 父组件汇总与子组件明细分栏：每个父实例一行，显示子数量；支持名称/路径/资产 ID 搜索、子项多选、定向解绑和显式整组解绑。
- 连续点选按 SW 选择事件累计子组件；每次加入后清理 SW 选择，重复实例去重。允许手动多选追加、移除子项和清空本轮。
- 同级同款批量添加：明确操作后，将与种子组件同一 CAD 父级、同源身份/文件及同版本的普通 Asset 加入待确认清单。不会跨重复子装配推断归属。
- 应用成功自动清空本轮；取消或校验失败保留草稿。批量确认改用可滚动窗口。
- 链式模式：单个子组件自动成为下一父；多个子组件由用户从下拉框选择一个分支。已有关系明细也可直接接续为父，保留上游边并继续校验接口、角色、单父和无环。
- 面板提供“保存总装配”，使用强类型 Save3 和已有原生存储事件。业务关系和导出 Schema 均保持 1.0，不迁移已有记录。
- 单次批量应用缓存端点解析结果，避免对 200 个子实例反复执行成对 COM 解析；缓存不跨操作复用。

## 验证

112 项自动回归全部通过，包括新增的 7 项交互状态及批量解析测试；隔离契约构建与真实 Interop Release 构建通过。构建环境的 targeting pack 警告与 rc1 相同，详见[先前验证记录](INSTANCE_BINDING_TEST_RESULTS.md)。

实机测试模型：`artifacts/binding-ui-20261103/Binding-UI-200.SLDASM`。它使用独立复制的测试零件，含 2 个架子与 200 个子组件，测试接口允许验证多层链。未向用户总装配添加测试关系。

| 场景 | 结果 |
| --- | --- |
| 快速连续三个单选 | SelectionMgr 每次替换原选择；原生面板累计全部三个实例，不需逐次点“添加” |
| 同级同款批量添加 | 从三个种子补齐 200 个独立子实例，已在清单的实例不重复 |
| 200 项确认 | 可滚动列表显示原父/新父，确认后待选清单和 SW 选择清空 |
| 分组展示 | 左侧仅 1 个父组件行、子数 200；右侧保留全部 200 条明细 |
| 多子链式分支 | 200 子应用后不擅自选父，下拉框选择 tip-1 后接续 |
| 单子链式接续 | tip-1→rack-2 成功，rack-2 自动接续下一父；原 rack-1→200 tips 保留，总数 201，汇总父数 2 |
| 保存、重开与修复 | 初次实机发现动态 Save3 的 DISP_E_BADINDEX，已改为强类型 API。重开保留 201 条关系；定向解除链末端一条，点击面板保存后 200 条保留、状态变为已保存/有效；独立读取持久化记录确认 200 条 |

证据目录：[artifacts/instance-binding-ui2-evidence](../artifacts/instance-binding-ui2-evidence)。`grouped-200.txt` 和 `chained-201.txt` 是原生界面控件记录；`tests.log`、`contract.log`、`production.log` 为最终构建输出。测试选择由真实 SW API 准备，新增面板操作通过原生窗口执行。

已有用户装配在升级前确认所有文档 dirty=False，正常退出 SW 后升级并恢复打开。最终用户目录升级的注册备份：`%LOCALAPPDATA%\SolidWorksAssetExporter\UpdateBackups\20261103-115944\com-codebases.json`；最早 rc2 前的 `20261103-115031` 可退回 rc1。

本次交互改进不改变导出协议；消费方联调、真实 NAS 上传及先前未验收的 P1 范围仍以原记录为准。安装和操作见[实例承载关系协议](INSTANCE_BINDING_PROTOCOL.md)。
