# SOLIDWORKS 资产与承载关系

使用 `solidworks-assets` MCP。先查看客户端暴露的工具或 MCP `tools/list`，以实际可用的工具和参数为准。调用 `assembly_context` 核对目标总装、活动配置、可写和保存状态。装配工具都使用该次读取的 `document_path` 和 `configuration`。分页读取 `asset_list`、`binding_list` 直到 `next_offset` 为空。关系使用完整 `instance` 区分重复件，属性写入按 `source_path` 作用于同文件的全部实例。变更目标装配或配置后重新读取上下文。

换机或连不上 MCP 时，先核对 Codex 配置中的 `SolidWorksAssetExporter.Mcp.exe` 和已加载的 SOLIDWORKS Add-in 版本，并确认两者在同一 Windows 用户会话中运行。按仓库 README 的安装步骤配置。打开一个已保存的总装，用 `tools/list` 和 `assembly_context` 验证连接。

## 识别资产并填写自定义属性

新项目先用 `component_list` 枚举零部件、子装配体和现有属性，逐页读取至 `next_offset` 为空。它也包含尚未标记为 Asset 的节点。已有 Asset 边界内部的零件按其所属资产处理。若客户端缺少清单或属性计划、应用工具，应报告缺少从零分类所需的能力。旧版 `asset_list` 可继续盘点已识别资产。

1. 根据项目设计、接口表、设备清单或经核实的同款用法，判断零部件或子装配体是否要独立识别、引用、导出或参与承载关系。有依据时设置 `is_asset` 为 `"1"`。明确属于普通几何或 CAD 分组的节点可标为 `"0"`。螺钉、外壳或内部机构等随所属设备整体导出的零件通常留在该边界内。BOM 条目、CAD 层级和文件名只能辅助定位。优先从装配树上层确定导出边界，避免同一个可复用总成与其内部组成件被分别标记。切换边界后重读清单再处理余项。
2. 已确认独立的资产按实际用途选主分类。由机器人抓取、携带或转运的对象使用 `movable`。固定且与机器人进行放置、取出或加工交互的设备或治具使用 `station`。固定的框架、外罩等纯结构使用 `structure`，业务上可直接归 Lab。`robot` 用于有独立机器人资产引用的运动执行设备。按实际能力填写 Tool、Fixture 或快换角色，快换盘需要匹配的 `quick_changer_side`。用证实的设备名填写 `零件名`。资产描述只写硬件用途、规格、容量和机械接口。仅直接盛放样本或试剂的容器启用 `can_hold_contents`。SOLIDWORKS 文件级属性使用 `1` 或 `0`，manifest 顶层输出 JSON 布尔值。明确的非资产工位分组可填写 `is_workstation` 和 `workstation_name`。
3. 每个源文件只计划一次。用当前的 `instance`、`source_path` 和 `properties` 调用 `asset_properties_plan`，仅传有依据且需要变更的字段。若图纸确认试管架固定并供机器人放取，可传 `{"is_asset":"1","class":"station","is_fixture":"1","零件名":"试管架","设计目的":"定位和暂存试管"}`。按设计资料可补填布局可调性、设计原理及升版说明。已确认的接口与总槽位可一并填写，`accepts_interfaces` 用英文分号分隔，`slots_num` 用非负整数字符串。普通资产版本由插件维护。Robot 的 `设计目的` 使用已发布机器人名称，`asset_version` 使用已核实的外部引用版本。
4. 核对计划中的属性及对现有关联的影响。获准维护时用同一组参数加 `plan_token` 调用 `asset_properties_apply`。用 `component_list` 和 `asset_list` 核实属性与边界。若返回 `interface_issues`，按下一节依据补齐角色要求的接口，再预检导出。
5. 独立边界、主分类或同源用途不明确时，立即请人工确认，给出完整实例、来源文件及缺少的设计证据。继续处理相互独立且有依据的源文件。

## 拆分资产、坐标基准与门状态

- 同一设备拆分出的不同资产使用互不重合的实际装配原点。固定主体沿用已核实的基准，活动件以自身的滑轨定位面、铰轴或装配定位特征定义可重复测得的原点和方向。把原点变换到同一总装坐标系比较，并核实导出几何所用的基准。当前导出器使用模型默认坐标系，单独建立命名坐标系不会改变导出基准。
- 拆分或重定基准前记录每个相关配置的实体世界位姿和原生 CAD 配合。同步补偿子件局部位姿与上级实例位姿，使实体保持原来的世界位置和朝向。保存后逐实例核对几何、配合端点、铰轴或滑轨方向、限位和业务承载位姿。保留原生同源同名资产时核对 UUID，预检受影响的资产版本和装配版本。
- 同款门与同一种主体机械接口的组合，在同一导出范围内统一为一种展示状态。以设计资料或用户确认的状态为准，用铰轴、滑轨、配合限位及实际几何确认开关方向和程度。发现同组混有开门、关门或不同开度时，列出完整实例及当前位姿，确认统一状态后才调整相应活动自由度。保留原 CAD 开合能力和配合限位。
- 只交付一种装配状态时，绑定该状态的可拆件。若任务要求交付同一可拆件的两处可用位置，例如离心机盖的闭合位和工具底板的停放位，分别使用经原生配合和位姿核验的同源、同版本 CAD 实例。每个实例只绑定实际承托它的父级。包内两条关系共用一个资产版本，记录两处安装位姿，实际占用和备件数量另按项目设计确认。

## 固定二维码

依据实际装配几何及固定方式，将随设备或载具固定移动的二维码实体或专用安装板归入所属资产几何。按固定的机械归属确定主体，二维码作为其几何组成部分保留实际位置和朝向。确认 `has_QRcode=1` 时，用已有 `QR_num`、`QR_size`、`QR_spacing` 表达实际数量、单码尺寸和间距，沿用经核实的原属性及项目测量单位。有缺项、标识身份不明或实际数量与原属性不符时，记录具体实例和缺少的证据。

## 从零建立关系和接口

1. 收集项目明确的装配要求、图纸、接口表或已确认的重复设计。用 `binding_evidence` 获取实例的 CAD 上级、固定状态、装配坐标和可读取的双端 CAD 配合。配合用来定位候选件，结合组件用途和实际安装方式判断方向。CAD 层级、固定状态、原点距离和同名都只能作为辅助证据。配合数据缺失时可用明确的设计资料继续。
2. 按业务用途判断实际方向。接收、定位、停放或承载的一侧是父级，被放置、装入或挂载的一侧是子级。若独立的中间托座实际承托载具，逐级记录底板、托座、载具的关系。每个子实例至多绑定一个直接业务父级。需要表达多个经确认的承载位置时，优先复用已有的同源原生实例。只有缺少实例且用户授权维护 CAD 时才复制，并核对目标世界位姿和两个独立的持久引用。永久固定且没有业务承载父级的 `structure` 留在 Lab 业务层。仅把可用的普通资产实例作为显式关系端点。Robot 保持外部资产引用。
3. 有有效的子接口时沿用它。空接口可根据已确认的安装规格、制造商型号、项目接口表或经核实的同款已用接口定义。只要声明机械 `accepts_interfaces`，资产自身就要有经核实的 `connection_interface`。固定工位也按实际安装面、定位基准或紧固方式核实向上接口。证据不足时列出缺少的依据并保留真实的子级接口。用 `interface_catalog` 查已有命名，按实际规格复用名称。新增名称使用项目命名规则，包含能区分兼容性的规格，测不到或未获证实的尺寸省略。一个源文件的子连接接口只能有一个值。发现同源实例需要不同接口时，立即报告冲突并请人工确认设计。父级接受列表保留原有兼容项并追加已确认的子接口。槽位和容量按下一节核对。
4. 按下一节选定要显式记录的代表关系和实例关系，对每组已证实的父级及其子级调用 `binding_plan`。传入 `parent` 和 `children`，只在需要补空接口且全组适用时传入 `connection_interface`。已知父资产设计容量时可传 `slots_num`。检查 `source_changes` 和 `relations`。已有子接口不同的组分开处理。若快换盘等角色同时要求向上和向下接口，而单组计划无法满足，先用 `asset_update_interfaces` 一次写入已证实的两侧接口。计划通过并且用户已授权维护时，用原参数加返回的 `plan_token` 调用 `binding_apply`。以结果中的保存状态和重新读取的 `binding_list`、`asset_list` 核实关系和属性。
5. 一旦发现父级候选有歧义、接口规格或兼容性未证实，立即提醒人工确认，提供完整实例路径和缺失的证据。继续处理其余相互独立且已证实的关系。同源实例可以共享已证实的接口，承载父级仍逐实例判断。若无法确认接口或容量适用于其他已知的同源用途，暂缓该源文件的变更。工具校验检查数据和协议，业务承载方向与机械兼容性以项目证据为准。

例如装配几何确认 `架-1` 有 24 个 `试管.D20` 槽，两个已定位的子实例为空接口，给 `binding_plan` 传下列参数。计划通过后将返回的 `plan_token` 加入参数再调用 `binding_apply`。

```json
{
  "document_path": "C:\\CAD\\新项目.SLDASM",
  "configuration": "Default",
  "parent": "工位-1/架-1",
  "children": ["工位-1/试管-1", "工位-1/试管-2"],
  "connection_interface": "试管.D20",
  "slots_num": 24
}
```

如果客户端只发现旧版工具，使用 `asset_list` 和 `binding_list`，结合项目设计资料确定关系和接口。先对每个相关源文件调用 `asset_update_interfaces`，再调用 `binding_add`。手动构造接受列表时保留已有项。`sync_accepts_from_bindings` 读取已保存关系，首次建组应先维护接受接口。追加前检查子实例当前的直接业务父级，已有不同父级时按本节的单父规则处理。

共享接口目录沿用万象现有数据接口，在 NAS 的 `asset-interface-catalog/v2/` 中为每个已确认的机械接口保留一个 JSON 文件。用 `interface_catalog` 查询，按项目授权追加。维护范围是接口数据，万象服务和同步配置按独立任务管理。

## 槽位、子级和位姿核对

- 只给装配体几何证实存在的物理安装或承托位置标槽。用定位面、配合或实际容纳形状核对每个位置的用途与可达的安装位姿。槽位总数 `slots_num` 是同一父级的设计容量，包含空槽，容量未知时省略。同一个真实槽位的备选子级共用槽位，分别保留各自的最终安装位姿。
- 仅当源文件的 `slots_num > 0` 时填写 `slot_type`。普通承托槽选 `place`，按实际机构选 `mount`、`clamp`、`thread`、`press_fit` 或 `snap_fit`。`engagement` 独立定义，包括无槽但可以与主体接合的部件。默认选 `loose`，保持局部相对位姿时选 `tight`，有旋合结构时另行核实接合约束。提供安装位的主体是父资产，例如瓶为父资产，瓶盖或夹持环为子资产。实例的接合和松开由消费端控制，局部相对运动独立于外部固定、外壳和停放约束。
- SOLIDWORKS 文件级自定义属性是唯一来源。原生属性面板和插件“接口属性 / 建议…”的固定下拉框读写同一文件属性，也可通过 `asset_properties_plan` 和 `asset_properties_apply` 写入。原生模板无法按数字条件隐藏控件，零槽或容量未声明时在原生 `slot_type` 留空或选“不适用（无槽）”。插件仅在槽数大于零时显示它。自由文本只开放 `设计目的`、`设计原理` 和 `升版说明`。核验改动时重新读取文件属性。
- 同源、同资产版本且引用同一 CAD 配置的父资产，优先选择一个实际满载、一槽一子、无共槽备选的代表实例，逐个记录各独立设计槽位的绑定。其它等效实例可以复用这个槽位模板，空载或部分装载时可以省略重复的模板关系。不同引用配置、不同几何槽型或不同接口用途分别核验。
- 已保存的重复模板关系可在后续清理。先只读核对当前配置、完整父子实例路径、关系 ID、槽位、安装位姿和原生配合，列出拟解除项及保留的代表。用户授权后，只解除已证实能由代表等效覆盖的重复业务绑定。保留代表上每个已占用的独立槽位、具体实例的承载归属和门盖闭合关系，以及共享槽位的不同候选、各自的安装位姿和现有 CAD 配合。保存后重读 `binding_list` 并运行 `asset_export_preview`，确认代表仍覆盖各真实槽位，必要的实例关系仍完整。
- 对同一子资产在可对应的同槽型位置比较位姿，把它们换算到各自对应的槽基准再比较平移和旋转。发现明显偏离多数的情况，列出完整父子实例路径、对应槽位、平移差和旋转差，请人工确认。保留实际 CAD 摆位和当前记录，等待确认后再作调整。
- 用两个独立来源验证容量。按实体孔位、设计图纸或已确认规格填写 `slots_num`，从当前保存的承载关系统计观察到的直接子级和物理占用。同一共享槽只算一个槽位。不要用已绑定数生成或覆盖设计容量。已验证一个一槽一子、无备选的满载代表后，其它相同实例的空载或部分装载不必重复提醒。发现超容量、代表缺失或几何无法证实时，列出相关实例请人工核对。
- 导出预检会对缺少容量声明的固定夹具、接受机械接口的资产和已有绑定子级的资产提示 `slot_capacity_undeclared`，并在机械兼容接口与零容量并存时提示 `zero_capacity_with_mechanical_interfaces`。已核实没有独立槽位时填写 `0`。机械固定的工具属于工具侧快换总成时，该总成保留机械接口并可声明零个独立槽位。容纳能力使用 `can_hold_contents`，实际绑定超出容量时仍逐实例核对。
- 用实际摆位下的实体、有效配合和安装面核对代表父子件是否直接接触。发现可验证的非预期间隙或穿透时，记录完整实例和量测值，请人工检查。已知装配留隙、过盈或螺纹配合须依工程证据判断。包围盒只能筛选候选，不能证明实体接触或穿透；几何无法取得时记为未确认。

## 验证与发布

- 写入前核对 CAD 文档已保存。碰到未保存修改或只读文件，报告具体路径。`binding_apply` 会重新校验。引用失效时，先确认该实例在目标配置中的抑制状态、源文件、完整路径、配合和安装位姿，再修复关系。遇到计划失效或写入中断，核对已保存文件，重新读取属性和关系后再试。
- 导出前用 `binding_list` 检查端点、接口和单父级约束，再用 `asset_export_preview` 核对范围、版本和诊断。预览会读取万象注册表。`asset_export` 使用插件已保存的目录和发布配置，维护必要版本并再次校验。通过预检后用 `export_project` 指定装配包范围。发布时传 `upload: true`，保留并报告非阻断提醒。仅在用户明确要求提交解析时启用 `notify_assembly_parser`。只上传的任务使用关闭解析通知的配置，调用前核对插件开关。
- 检查 `exported`、`upload` 和 `upload_error`，从上传日志确认 HTTP 状态和时间。报告已发布的 assembly UUID、版本、NAS 路径和文件数。如按授权提交解析，另报通知的目标地址、时间和 HTTP 状态，收到 202 时附 `event_id`。要求核验远端时，通过现有万象接口读回报告、关系文件和 XML，核对版本、数量和 SHA-256。原 CAD 父级与业务承载父级分别从 XML 与关系文件读取。
